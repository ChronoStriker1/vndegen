# RGSS runtime provenance

VNDegen runs RPG Maker XP, VX and VX Ace games on its own RGSS runtime, written as a clean-room implementation. Its
code doesn't derive from mkxp, mkxp-z or any other GPL or LGPL implementation of RGSS: nobody working on it opened
their source, VNDegen's earlier mkxp-z files in `Engines/RGSS/` (apart from the list of upstream sources in
`UPSTREAM.md`), `scripts/rgss-engine.sh`, or the RGSS notes from that work. This file lists where each part's behavior
comes from.

## Sources

- **The games.** Their script sections (`Data/Scripts.rxdata`, `.rvdata`, `.rvdata2`), data files and graphics, read
  to learn what the runtime must provide: the classes and methods the scripts call, the Win32API calls they make,
  the files they read and write, and the binary layouts in their data. The test games are Test Games 14, 33, 37 and
  55 (`.audit/library/placeholder-map.txt`).
- **RPG Maker's help.** The help files of the official trial editors from rpgmakerweb.com (RPG Maker XP, VX and VX
  Ace, `RPGXP.chm`, `RPGVX.chm`, `RPGVXAce.chm`), read for behavior. The trial installers came over HTTP from the
  download links on rpgmakerweb.com/downloads, because the download server's TLS certificate chain is incomplete.
- **The original engine under Wine**, as a black box, only for questions the help and the games' files don't settle.
  Each use is listed below.
- **Permissive projects**, after checking their licenses: RPG Maker MV's corescript (MIT, KADOKAWA), RPGMakerDecrypter
  (MIT), and the stb and dr_libs libraries the runtime links (public domain or MIT, and MIT No Attribution).
- **Ruby.** MRI Ruby 3.4.9 under its 2-clause BSD license, with two small patches of VNDegen's own.

## Each part

| Part | Files | Sources |
| --- | --- | --- |
| Archives (`Game.rgssad`, `.rgss2a`, `.rgss3a`) | `CRGSS/core/archive.c` | The format as RPGMakerDecrypter (MIT, commit 465c88c3) reads it, in `RGSSADv1.cs`, `RGSSADv3.cs` and `RGSSAD.cs`: version 1's key 0xDEADCAFE stepping as key * 7 + 3, version 3's seed * 9 + 3 index key, and the data decryption four bytes at a time. Checked by extracting all three test archives. |
| Game files, case | `CRGSS/core/fs.c` | The help's Bitmap.new and Audio topics (archive and RTP searched, extensions optional). The search order (save folder, game folder, archive, RTPs) is VNDegen's own. Lookups ignoring case use VNDegen's shared `casepath.c`. |
| Color, Tone, Rect, Table | `CRGSS/core/rb_values.c` | The help's topics on the four classes. The `_dump` layouts come from the games' data files: Table is five int32 (dimensions, x, y and z sizes, cell count) and int16 cells, Tone four doubles, as Map001 and System files show. |
| Font, Bitmap | `CRGSS/core/rb_bitmap.c`, `bitmap.c`, `text.c` | The help's Font and Bitmap topics: defaults per version, `draw_text` squeezing wide text to as little as 60 percent, shadow (VX) and outline (VX Ace), `text_size`. | Viewport, Sprite, Plane, Window, compositor | `CRGSS/core/rb_drawables.c`, `render.c`, `window.c`, `scene.h` | The help's topics: z order with creation order breaking ties (and y first for VX Ace sprites), flash and color priority, bush depth and opacity, wave, tone, blend types. Window skin layouts follow the help's windowskin descriptions and the skins themselves; VX Ace's defaults (z 100, back opacity 192, padding 12) are from its Window topic. That windows in VX and VX Ace start with a contents bitmap, and that RGSS3 lets scripts read a disposed sprite's properties, come from the test games' scripts, which rely on both. |
| Tilemap, VX and VX Ace | `CRGSS/core/tilemap.c` | The help's Tilemap topic (z 0 and 200, the star flag). Tile ID ranges, the A1 to A4 sheet layouts, the floor, wall and waterfall quarter tables, A2 table edges and shadows from RPG Maker MV's corescript (MIT, KADOKAWA), commit 182e3144, `js/rpg_core/Tilemap.js`, which kept VX Ace's tile format. |
| Tilemap, XP | `CRGSS/core/tilemap.c` | The XP help's Tilemap topic for priorities and z. The 48-shape quarter table for XP's 96x128 autotiles was measured from RPG Maker XP's engine under Wine (`Engines/RGSSRuntime/tools/xp-autotile-probe`). The same probe in VNDegen's runtime matches the engine's screenshot in every pixel. |
| Graphics, Input, Audio | `CRGSS/core/rb_modules.c`, `audio.c` | The help's module topics. Default keys from the VX Ace help's "Playing a Game" page. Ogg loop points (LOOPSTART, LOOPLENGTH) as RPG Maker's documentation of looping BGM describes. Decoding is stb_vorbis, dr_mp3 and dr_wav; MIDI plays through VNDegen's shared `vnmidi`. |
| RPG module data classes | `Engines/RGSSRuntime/ruby/rpg*_data.rb` | Generated by `tools/gen-rpg.py` and `tools/emit-rpg.py` from the help's RPG pages: each class's superclass, attributes and initial values. The VX help labels BaseItem's definition `class Item`; the generator corrects that one name. |
| RPG module methods | `Engines/RGSSRuntime/ruby/rpg1.rb`, `rpg2.rb`, `rpg3.rb` | Written from the help's descriptions of each method (BGM.last, play, exp_for_level, the scope checks, Damage#eval, and so on). Where the help's prose and its definition disagree (VX Ace's `for_all?`, `Weapon#performance`), the definition's behavior was kept. XP's RPG::Cache, RPG::Sprite and RPG::Weather follow the XP help's descriptions; the animation cell layout (pattern, x, y, zoom, angle, mirror, opacity, blend) is the layout of the games' own Animations data. |
| Ruby 1.8 and 1.9 behavior | `Engines/RGSSRuntime/ruby/common.rb`, `patches/` | Ruby's own documentation of removed methods (`Fixnum`, `File.exists?`, `Object#taint`, `Hash#index`). XP and VX ran Ruby 1.8 (their strings carry no encoding); VX Ace ran 1.9. `ruby-marshal-bare-strings.patch` lets XP and VX saves leave out encodings as 1.8 did; `ruby-toplevel-class-variables.patch` restores 1.9's handling of class variables in a top-level `class << Module`, which Test Game 14's scripts use. |
| Win32API | `Engines/RGSSRuntime/ruby/win32api.rb` | Microsoft's documentation of each function the test games call (the list is in `docs/rgss.md`). |
| Movies | `CRGSS/core/rb_modules.c`, `audio.c` | The VX Ace help's Graphics.play_movie entry and its Movie Resources page (Ogg Theora from `Movies/`, centered, cut off where larger than the screen). The rest from RGSS3 under Wine, below. Decoding is VNDegen's shared `vnvideo`. |
| Message boxes | `CRGSS/core/rb_modules.c`, `host.c`, `EngineRGSS/RGSSMessageBox.swift` | The help's msgbox and msgbox_p entries (VX Ace) and print and p (XP and VX): the arguments' to_s, or each one's inspect on its own line, returning nil. The look and the return values from RGSS3 under Wine, below. |
| Threads, frames, the C interface | `CRGSS/core/host.c`, `game.c`, `include/vnrgss.h` | VNDegen's own design. |

## The original engine under Wine

- **Saves.** VX (Test Game 33): the game ships two PC saves, which VNDegen's runtime loads; a save VNDegen's runtime
  wrote loads in RGSS2 under Wine. VX Ace (Test Game 14): a save VNDegen's runtime wrote loads in RGSS3 under Wine.
  Evidence in `.audit/evidence/cr-rgss/run/`.
- **PC saves loaded in VNDegen.** New XP (Test Game 37) and VX Ace (Test Game 14) saves made through the original
  engines' menus under Wine load through Continue in the Linux host. Map, position and direction match the PC saves;
  screenshots show the same scenes. Evidence in `.audit/evidence/qw-rgss-pc-saves/`.
- **XP autotiles**, as above.
- **Movies and message boxes.** A test project of VNDegen's own (a Game.ini, a Scripts.rvdata2 with one script section,
  and three of the library's movies), run on RGSS301.dll from a library game under Wine and Xvfb: the movies are
  drawn at their own size in the middle of the screen, a 576x432 movie on a 544x416 screen matching the source frame
  cropped at its center, and the game's last frame stays around a smaller one. `Graphics.frame_count` runs on at 60 a
  second during a movie. Return, Escape, X, Space and Z pressed during an 11 second movie didn't end it early, while the
  same key presses closed a message box. `Movies/ya6vq-bvs2s` played the `.ogg` file of that name. `msgbox` and
  `msgbox_p` returned nil, and msgbox_p showed each value on its own line. Evidence in
  `.audit/evidence/rgss-movies/wine-probe/`.

## Uncertain points and how they were settled

- Bitmap blending onto a transparent bitmap, color and tone order on sprites, and the viewport tone's scope follow the
  usual source-over and tint formulas. The help doesn't give them, and the test games look right with them.
- Input repeat timing (24 frames, then every 6; XP 16 and 4) and the audio volume curve (squared) are estimates.
- Text metrics: stb_truetype with the font's Windows ascent and descent, sized so a font's height equals Font#size.
