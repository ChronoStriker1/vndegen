You can now keep a library of controller layouts: pick a built-in one for a game, change its buttons, and save your own. Buttons and tags also get true round ends, to remove the short vertical lines some people saw on iPhone and iPad.

## Downloads

- `VNDegen-0.23.0-macOS.zip` for Mac (macOS 15 or later). It is ad-hoc signed: right-click VNDegen and choose Open the first time, or run `xattr -dr com.apple.quarantine /Applications/VNDegen.app`.
- `VNDegen-0.23.0.ipa` for iPhone and iPad (iOS 18 or later). Update it from the AltStore or SideStore source (`https://raw.githubusercontent.com/ChronoStriker1/vndegen/main/altstore/source.json`), or sideload it with Sideloadly.

## New: controller layouts

- The button mapping sheet is now called Controller layout, on a game's page and in the VNDegen menu. Pick a built-in layout, change a game's buttons, and save them as your own.
- Edit, rename, or delete the layouts you saved. Editing one also changes every game showing it, and the edit screen says so. Deleting one leaves those games' buttons as they are.
- Picking a layout copies its buttons into the game, so changing a game's buttons later doesn't change the layout.

## Changed: Keyboard and mouse's D-pad

- The D-pad now matches Steam's template file: up 1, right 2, down 3, left 4. Before it was up 1, down 2, left 3, right 4.
- KiriKiri, TyranoScript, Flash, Artemis, AliceSoft, and NScripter games on the default layout start with the new order.
- Saved mappings keep their buttons. The exception is AliceSoft and Artemis games whose D-pad was exactly the old order. Those move to the new order once, so directions keep working in those games' dialogs.

## Fixes

- Buttons and tags now have true round ends, including the touch gamepad's shoulder buttons. If you still see short vertical lines at their ends, please say so on issue 10.
- Library refreshes do less work: engine detection stops at the first certain match, and folder scans skip a check they didn't need at their last level. Which games are detected doesn't change. Some unused engine code is gone.

## Known limits

- If you set the old D-pad order again on an AliceSoft or Artemis game, or put other digits on its D-pad, those keys step by what they send in its dialogs.
- A saved layout's games stop following it if an edit makes it match an earlier layout, since those games then show the earlier one.

## What wasn't tested

- No physical device was used. The lines on buttons could never be reproduced on a live screen here, so true round ends are the best-supported fix and not a proven one.
- A remapped button reaching a running game, and the new D-pad order in a real AliceSoft number box or Artemis dialog, which only unit tests cover.
- Which games bind keys 2, 3, or 4. No binding was found in the scripts that could be read, 8 KiriKiri and 2 TyranoScript games with thin coverage on some, and most of the library wasn't checked.
- Typing a layout's name on a hardware keyboard.
