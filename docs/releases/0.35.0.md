Visual novel, Flash and older RPG Maker games start on controller layouts that fit them, so buttons that did nothing or did the wrong thing now work.

## Downloads

- `VNDegen-0.35.0-macOS.zip` for Mac (macOS 15 or later). It is ad-hoc signed: right-click VNDegen and choose Open the first time, or run `xattr -dr com.apple.quarantine /Applications/VNDegen.app`.
- `VNDegen-0.35.0.ipa` for iPhone and iPad (iOS 18 or later). Update it from the AltStore or SideStore source (`https://raw.githubusercontent.com/ChronoStriker1/vndegen/main/altstore/source.json`), or sideload it with Sideloadly.

## New

- A new built-in controller layout, "Visual novel", is what KiriKiri, NScripter, Artemis and AliceSoft games start on. A reads on (Return), B right clicks, which opens the menu or hides the text window, X holds Control to skip, Y and Menu press Escape, LB and RB turn the mouse wheel for the message history, and the D-pad and left stick are the arrow keys. Before, A hid the text window in KiriKiri and Artemis games and cancelled menus in AliceSoft's older games, and B, X, Y, the D-pad and the left stick did nothing.
- Flash games start on "Mouse", where A and RT click and both sticks move the pointer.
- RPG Maker XP, VX and VX Ace games start on "RPG Maker controls", which now puts the A, S and D keys, RPG Maker's X, Y and Z buttons, on LT, RT and View. A prompt such as "push the S key" can now be answered with a controller.
- In Wolf RPG Editor games, RT holds Control, which many of them use to skip messages.

## Changes

- Games still on their engine's old default layout move to the new one the next time they start. A game where you picked "Keyboard and mouse" while it was already the default moves too; pick it again from the controller layout sheet. Games whose buttons you changed keep them, and saved layouts are unchanged.
- "Keyboard and mouse" stays in the layout list as it was, and TyranoScript games still start on it.
- A game where you picked "RPG Maker controls" keeps its buttons but no longer shows that layout as checked, because the layout gained three buttons.
- In an Artemis game's own dialogs, the arrows move, a right click cancels, and Escape from a controller button finishes the on-screen keyboard. Under "Keyboard and mouse", Menu in such a dialog now finishes it where it used to cancel; B still cancels.

## Known limits

- In three Artemis games the D-pad's left and right are the game's quick save and quick load. Quick load asks before it loads.
- In a KiriKiri game, the D-pad moves the game's own button focus, and A then presses the focused button until the next click, as a keyboard does on the PC.
- In AliceSoft's Rance 02, the command menu reads only the pointer, so the D-pad and A do nothing there. The right stick moves the pointer.
- A Flash game that uses keys, not the mouse, needs "Keyboard and mouse" picked by hand.
- Evenicle stops as it starts (#84), and Violated Hero stops partway through its opening (#85). Both were there before this release.

## What wasn't tested

- No physical device or hardware controller was used. Buttons were pressed through the app's test hooks in the Mac app, and with the touch gamepad on the iPad simulator.
- Each engine's changed buttons were pressed in one game: Violated Hero (KiriKiri), one Artemis game, Rance 02 (System 4), Monster Girl Encyclopedia RPG (RPG Maker VX Ace) and Pocket Gal Hunter (Wolf RPG) in the Mac app, and Rance III (System 3) on the iPad simulator. NScripter's keys were pressed in the Linux test build only.
- Flash on "Mouse": a click wasn't seen landing on a button in the app. The layout shows on the game, and a left click advancing a Flash game was seen in the Linux test build.
- RPG Maker XP and VX games weren't run, only VX Ace. LT and View were seen as keys in the Linux test build, not in the app.
- Not looked at on an iPhone.
- No code review was done on this release.
