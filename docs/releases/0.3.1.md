Fixes for Ren'Py on Mac and for Ludusavi restores.

## Downloads

- `VNDegen-0.3.1-macOS.zip` for Mac (macOS 15 or later). It is ad-hoc signed: right-click VNDegen and choose Open the first time, or run `xattr -dr com.apple.quarantine /Applications/VNDegen.app`.
- `VNDegen-0.3.1.ipa` for iPhone and iPad (iOS 18 or later). Update it from the AltStore or SideStore source (`https://raw.githubusercontent.com/ChronoStriker1/vndegen/main/altstore/source.json`), or sideload it with Sideloadly. On iPhone and iPad, Ren'Py games are detected and listed but do not run yet.

## Fixed

- A game you just quit can't be started again until it has stopped and its automatic backup is done, so two copies of the game never write the same saves. Restore, Undo, and Back up now wait for it as well. If the backup is stuck, for example on a network share that went away, the game can start again 20 seconds after it stopped.
- Ren'Py games whose scripts sit deep inside `game/`, such as `game/scripts/act1/scenes/`, are detected.
- If a Ren'Py game's `game/saves` folder can't be read on its first launch, the launch fails with a message and the next launch tries the import again. Before, the game started without the PC saves.
- A Ludusavi restore or Undo refuses to write through a symlink that leads out of the game's save folder.
- `scripts/renpy-compat.sh` refuses to delete a run folder that a symlink puts inside a game folder.

## Known limits

- The game window opens exactly over the VNDegen window. Hiding the library while the game runs and bringing it back afterward has not been checked on an unlocked desktop yet.
- Changes to button mapping made while a Ren'Py game runs apply on its next launch.
- Opening the VNDegen menu from a Ren'Py game's main menu blanks that menu until you resume.
