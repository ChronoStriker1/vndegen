RPG Maker MV and MZ games and Godot games get a controller layout suggested from their own files.

## Downloads

- `VNDegen-0.34.0-macOS.zip` for Mac (macOS 15 or later). It is ad-hoc signed: right-click VNDegen and choose Open the first time, or run `xattr -dr com.apple.quarantine /Applications/VNDegen.app`.
- `VNDegen-0.34.0.ipa` for iPhone and iPad (iOS 18 or later). Update it from the AltStore or SideStore source (`https://raw.githubusercontent.com/ChronoStriker1/vndegen/main/altstore/source.json`), or sideload it with Sideloadly.

## New

- Suggested controller layouts. For RPG Maker MV and MZ games and Godot games, VNDegen reads the game's own files and puts keys the game uses, such as message skip, auto mode and hiding the text window, on controller buttons that did nothing before. It shows as "Suggested for this game" in the controller layout sheet, and each button it added says what it does. [docs/controls.md](../controls.md) has the details.
- The suggestion becomes the game's starting layout without asking. Every button the engine's layout already uses stays as it was. The engine's own layout is still in the list, and Reset returns to the suggestion.
- Games already in your library get a suggestion too. A game whose buttons you changed keeps them, and you can pick "Suggested for this game" from the list.
- The game's files are read on the device. Nothing is sent anywhere, and the game doesn't run to find its keys.

## Known limits

- RPG Maker MV and MZ: the suggestion comes from the message plugins MessageSkip, UTA_MessageSkip and MessageWindowHidden, and from keys other plugins add. Of 84 games read, 48 got a suggestion. A game with its own controller setup plugin gets none, on purpose.
- Godot: a game that handles the controller itself in its scripts gets no suggestion, and neither does one whose scripts VNDegen can't read, such as compressed ones, or one written in C#. Of 6 games read, 1 got a suggestion, a game that reads no controller at all. Scripts kept inside a game's scenes aren't checked.
- A Godot button's second line is the action's name as the game wrote it, so it can read "Moveup" or "Rightmouse".
- The files are read the first time a game's page opens or the game starts. A game started straight from the library before that finishes starts on its engine's layout and gets the suggestion the next time.
- The Godot game that got a suggestion has a title screen that only the pointer can use. A controller's right stick moves the pointer. The touch gamepad has no sticks, so on a touch screen its title needs the Mouse control method.
- Other engines get no suggestion yet.

## What wasn't tested

- No physical device or hardware controller was used.
- The layout sheet was looked at in the Mac app and on the iPad simulator with one RPG Maker MV game and one Godot game. It wasn't looked at on an iPhone.
- The suggested buttons were pressed in those two games on the iPad simulator, with the touch gamepad: skip, auto and hide window in the RPG Maker game, and the D-pad, A and the map button in the Godot game. They weren't pressed in the Mac app.
- The other 47 RPG Maker games' suggestions were made by the reader on Linux and not looked at in the app.
- No Godot 3 game was among those read. Godot 3 is covered by hand-written test files only.
- Updating with a game whose buttons were changed in an earlier version was tested in the unit tests, not in the app.
- No code review was done on this release.
