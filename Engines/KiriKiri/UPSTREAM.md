# KiriKiri engine upstream

VNDegen runs KiriKiri games on krkrsdl3, an SDL3 port of the Kirikiri 2 and Kirikiri Z engine derived from Kirikiroid2.

## License

krkrsdl3 carries the Kirikiri license in `krkrsdl3/LICENSE`: a BSD-style license with a krkrsdl3 clause. A binary distribution must include the copyright notice, the conditions, and the disclaimer in its documentation, so VNDegen's app must show the text of `krkrsdl3/LICENSE`. The krkrsdl3 clause requires anyone who distributes ports of commercial games that run on modified krkrsdl3 to publish the modified source under the same terms. This folder, in a public repository, does that.

Bundled third-party code keeps its own license: SQLite (public domain), the LZMA SDK in `plugins/Kirikiroid2/7zip` (public domain), and minizip (zlib license). The Bison-generated parsers in `tjs2/*.tab.*` carry Bison's exception, which lets them be distributed under the engine's license. Two parts come from the Android Open Source Project under the Apache License 2.0: DroidSansFallback.ttf, and `core/utils/VelocityTracker.cpp` and `VelocityTracker.h`, which the Kirikiri Z authors adapted to track touch velocity. Their notices and the license text are in `AOSP-LICENSE.txt`, which `scripts/kirikiri-engine.sh` copies into the license folder the app lists. Dependencies from vcpkg keep theirs: SDL3, SDL3_ttf, zlib, and libpng (zlib-style), FreeType (FreeType License), libjpeg-turbo (BSD-style and IJG), libwebp, libogg, libvorbis, Opus, and opusfile (BSD), oniguruma (BSD), plutovg (MIT), and glm (MIT).

## FFmpeg

VNDegen's movie decoder, `vndegen/movie_decoder.cpp`, uses FFmpeg 8.1.2. vcpkg builds it from the overlay port in `ports/ffmpeg/`, whose first commit is vcpkg's port unmodified. It has two changes. The x86_64 macOS slice builds without FFmpeg's x86 assembly (`--disable-x86asm`), so the build Mac needs no nasm, and the configure options gain the component list:

```
--disable-everything --disable-network
--enable-demuxer=mpegps,mpegvideo,asf,mov
--enable-decoder=mpeg1video,mpeg2video,mp1,mp2,mp3,wmv1,wmv2,wmv3,vc1,wmav1,wmav2,h264,hevc,aac
--enable-parser=mpegvideo,mpegaudio,vc1,h264,hevc,aac
--enable-hwaccel=h264_videotoolbox,hevc_videotoolbox
```

The port adds the rest of the configure line: `--enable-pic --disable-doc --enable-runtime-cpudetect --disable-autodetect`, the platform options (`--target-os=darwin --enable-appkit --enable-avfoundation --enable-coreimage --enable-audiotoolbox --enable-videotoolbox` for macOS, `--enable-avfoundation --enable-coreimage --enable-videotoolbox` for iOS), the libraries that `vcpkg.json` selects (`--enable-avcodec --enable-avformat --enable-swresample --enable-swscale --disable-avdevice --disable-avfilter --disable-ffmpeg --disable-ffplay --disable-ffprobe`), and a `--disable-` option for every optional external library. The port's `gpl`, `nonfree`, and `version3` features stay off, so the line has no `--enable-gpl`, `--enable-nonfree`, or `--enable-version3`, and FFmpeg's configure reports `License: LGPL version 2.1 or later`. The `mpegvideo` demuxer is there because MPEG program streams identify their video streams by probing with it. FFmpeg enables the `h263` decoder too, which `wmv1` and `wmv2` need.

With FFmpeg and the player, the iOS device framework grew from 11.0 MB to 16.7 MB.

FFmpeg is linked statically. LGPL 2.1 allows that when the recipient can relink the program against a modified library, which VNDegen's public source permits. The app must show FFmpeg's LGPL notice alongside the krkrsdl3 license.

## Left out

- The movie player in `core/media/movie/`. Its `CDVDMsg*`, `CDVDMessageQueue`, `VideoReferenceClock`, and `VideoPlayer*` classes derive from Kodi's VideoPlayer, which is GPL-2.0, and VNDegen stays free of GPL code. `krmovie.cpp`, `krmovie.h`, and `krnull.h` remain, as the interface the rest of the engine calls.
- The `wuffmpeg` audio decoder (`plugins/wuffmpeg.cpp`), which read sound files through FFmpeg. The engine decodes Ogg Vorbis, Opus, and WAV sound files, but not formats only FFmpeg reads, such as MP3. FFmpeg is built for movies only.
- The BPG image loader (`plugins/Kirikiroid2/LoadBPG.cpp`). It needs libbpg, which is LGPL, and BPG is a Kirikiroid2 conversion format that Windows games do not ship.
- The OpenGL and Vulkan render backends and their shaders. VNDegen renders with the software backend, which presents through SDL3's renderer on Metal.
- The `environ/` folders for Android, OpenHarmony, WebAssembly, Windows, Linux, SDL2, and the console build. `environ/apple/apple_video.mm` and `environ/PlatformVideo.h`, an unimplemented system video interface, are removed too.

## VNDegen's additions

- `vndegen/ciphers.cpp`: native decryption of encrypted archives. Each scheme is one row in its table.
- `vndegen/movie_decoder.cpp`: decodes a movie with FFmpeg on a worker thread, reading it through the engine's storage streams, so archive ciphers apply. Audio stays in packets until the sound output has room for it, however far the decoder reads ahead for video. `vndegen/movie_test.cpp` builds `KiriKiriMovieTest`, which decodes movies with it and checks frame counts, audio, and seeking.
- `vndegen/movie_player.cpp`: the movie player behind `krmovie.h`'s `iTVPVideoOverlay`. It shows each decoded frame when the engine's clock reaches it, as an overlay sprite over the window or into the two bitmaps a layer-mode `VideoOverlay` shows, and plays the audio through the engine's sound output. The clock is the engine's tick count, which stops while the engine is paused, kept within 40 ms of the audio played. `vndegen/movie-check/startup.tjs` is a script-only game that `scripts/kirikiri-movie-check.sh` runs to check overlay and layer mode, loops, segment loops, period events, seeking, and pausing.
  Left out: only the first audio stream plays, and `audioBalance`, `playRate`, the picture adjustments such as `contrast`, and the mixer mode's mixing bitmap have no effect. Mixer and Media Foundation modes draw as overlay mode does. Movie audio follows `audioVolume` but not the global sound volume.
- `vndegen/sigcheck.cpp`: a `sigcheck.dll` stub. Its `Window.checkSignature` reports every file's signature as valid without checking it.
- `vndegen/steam.cpp`: stubs for Steam builds. `krkrsteam.dll` defines a `Steam` class with the members of `DummySteam.tjs`, the stand-in in wamsoft's plugin source: its achievement, cloud, screenshot, broadcast, and DLC calls do nothing, it reports no Steam user, `initialized` is true, and `getLanguage` returns Steam's name for the system's preferred language, or `english`. `DrawDeviceForSteam.dll` makes `DrawDeviceForSteam` the engine's `Window.BasicDrawDevice`. `steam_api.dll` needs nothing, since linking a missing plugin is not an error.

## VNDegen's changes to upstream files

1. `core/archive/XP3Archive.cpp`: reads hashed-name archives. Some Kirikiri Z archives store each file under the MD5 of its name and keep the real name in an `eliF` chunk just before the `File` chunk. The index reader maps each `eliF` name to the `File` chunk after it.
2. `core/media/image/GraphicsLoadThread.cpp`: a name the archive lacks, queued by `System.touchImages`, threw on the image loader's thread and aborted the process. It is now reported as a load error, as decode failures already were.
3. `core/media/movie/krmovie.cpp`, `core/media/movie/krnull.h`: every movie logs "video not supported, skipping <name>" and is replaced by one null player whose `Play()` posts a single `EC_COMPLETE`, so the movie ends at once and a game waiting on it continues. Upstream's null layer player posted `EC_COMPLETE` on every frame. Change 37 puts VNDegen's player in front of it.
4. `environ/iOS/ios_core.mm`: drops the include of the removed `PlatformVideo.h`.
5. `plugins/Kirikiroid2/kirikiroid2.cpp`: no longer registers the removed BPG loader.
6. `core/utils/TVPSettings.cpp`: a `-gameroot=<dir>` option sets the project folder, which is `System.exePath`, the base for `savedata/`, and where plugins and fonts are looked up. Without it a `data/` folder became `System.exePath`, and games that list `System.exePath + "fonts/"` failed. Command-line options are now parsed before the paths so the option can take part.
7. `environ/sdl3/sdl3_utils.cpp`, `environ/Platform.h`: `TVPSetClockPaused` stops and resumes the engine clock. Paused time is left out of `TVPGetRoughTickCount`, so timers and transitions resume where they stopped.
8. `environ/sdl3/sdl3_audio.cpp`, `environ/PlatformAudio.h`: `TVPSetSoundPaused` pauses and resumes every open sound buffer's audio device.
9. `environ/sdl3/sdl3_app.cpp`, `environ/PlatformView.h`: mouse events are handled on iOS too, so VNDegen can inject them, and SDL no longer turns touches into mouse events there, since touches have their own handler. `TVPGetSDLWindow` exposes the engine's SDL window.
10. `environ/apple/apple_core.mm`: resources such as the fallback font are looked up in the bundle that contains the engine, which is the framework when the engine is embedded in an app, instead of the main bundle.
11. `core/archive/XP3Archive.cpp`, `core/archive/XP3Archive.h`: each archive detects its encryption when it opens, through `VNKKDetectCipher` in `vndegen/ciphers.cpp`, and keeps the scheme in `Cipher`. Reads decrypt with it unless a game's `xp3filter.tjs` has installed an extraction filter, which takes its place.
12. `core/media/font/TVPFont.cpp`: the scan of the game's `fonts/` folder passed bare file names to the font loader, which needs storage names, so a game with a `fonts/` folder stopped at startup with `Not supported media type ""`. It now passes each file's full name, and skips folders.
13. `core/utils/TVPSettings.cpp`, `core/script/tjsNativeSystem.cpp`, `core/archive/TVPStorage.cpp`, `core/archive/TVPStorage.h`: with `-gameroot`, `System.exeName` is the game's `.exe` in that folder, as on Windows, instead of the project data. Games check for files beside it, such as `<exe>.cf`. When the folder holds several, the `.exe` with a matching `.cf` wins, then a lone `.exe`. The value is no longer cached across games in one process.
14. `tjs2/tjs.h`, `tjs2/tjsObject.cpp`, `tjs2/tjsNative.cpp`, `tjs2/tjsScriptBlock.cpp`: `tTJSObjectPool`, which tracks live script objects so a stopped engine can delete the ones it leaked, is rewritten as a locked slot vector with a free list. Upstream's pool counted 0 of its 1024 starting slots, so growing it handed out slots still in use, and clearing it handed out indexes past its end. A second game in the same process then crashed in the `tTJSScriptBlock` constructor. Objects now always unregister in their destructors, and the pool deletes what is left by reading each slot again just before deleting it, so objects that a deletion frees along the way are not deleted twice.
15. `core/main/TVPWindow.cpp`: a window's destructor cancels its queued input events and window updates. `TVPClearAllWindows` deletes windows at engine shutdown without the script-side invalidation that used to cancel them, and the stale updates were delivered to the next game's freed windows.
16. `core/archive/TVPArchive.cpp`: an archive stream released after the archive handle pool has shut down, as script objects release theirs during engine shutdown, is closed instead of leaked. Each game leaked file handles until a later game could not open its archive.
17. `environ/sdl3/sdl3_file.cpp`: a file that cannot be opened for reading throws "cannot open storage". It used to produce a stream with no handle whose seeks returned -1.
18. `core/main/TVPApplication.cpp`: a script error during startup is logged and fails `StartApplication`, so `vnkk_start` returns an error. It used to escape as an uncaught exception and end the host process.
19. `core/script/tjsNativeMenuItem.cpp`: the shortcut key tables, whose absence is what makes the engine register `Window.menu`, are cleared with the script engine that owns them. Upstream cleared only the first table, and only once a game had created a menu, so after a game that failed before that, the next game had no `Window.menu`.
20. `core/utils/StringUtil.h`: `Trim` for `ttstr` trims leading and trailing spaces and control characters. Upstream's helpers tested the opposite condition and read past a one-character stack buffer, which AddressSanitizer reported for every font name.
21. `core/script/tjsNativeKAGParser.cpp`, `plugins/KAGParserEx/KAGParserEx.cpp`, `plugins/ExtKAGParser/ExtKAGParser.cpp`, `core/script/tjsNativeWaveSoundBuffer.cpp`: the parsers initialize their line position and `LineBufferUsing`, and the sound buffer initializes `BufferCanControlFrequency`. Copying a fresh parser or setting a sound's frequency read them uninitialized.
22. `core/render/gl/tvpgl.cpp`: the TLG5 and TLG6 decoders read 16- and 32-bit values at any byte offset with `memcpy` instead of misaligned pointer loads.
23. `core/utils/TVPSettings.cpp`, `core/archive/TVPStorage.cpp`, `core/archive/TVPStorage.h`, `core/script/tjsNativeSystem.cpp`: `-appdatadir=<dir>` and `-personaldir=<dir>` set what `System.appDataPath` and `System.personalPath` report, the Windows AppData and Documents folders, where some games keep their saves. Without them both stay the game folder, as before.
24. `environ/sdl3/sdl3_app.cpp`, `environ/PlatformView.h`: `TVPSetHostWindow` hands SDL an NSWindow and NSView to wrap instead of creating its own window. While it is set, the game cannot resize the window or make it full screen, since the host sizes it.
25. `core/main/TVPSystem.cpp`: `TVPTerminateSync`, which `System.exit` and an unhandled script error call, closes the game the way `System.terminate` does instead of calling `exit()`, because the engine runs inside VNDegen's process.
26. `environ/sdl3/sdl3_thread.cpp`: a thread waits to be resumed under its mutex, so a `Resume` that comes first is not lost, and `WaitFor` wakes a thread that was never resumed and lets it end. Stopping the engine after a failed start used to wait forever on the never-started image loader thread.
27. `core/archive/XP3Archive.cpp`: the `eliF` scan of change 1 compares each chunk's size with the bytes left in the index before adding it. A size near 2^64 wrapped the bounds check and left the scan on the same chunk forever.
28. `environ/sdl3/sdl3_utils.cpp`, `environ/Platform.h`, `environ/sdl3/sdl3_app.cpp`: `TVPResetClock`, called right after `SDL_Init`, forgets the paused time of change 7. `SDL_Init` restarts `SDL_GetTicks`, so the next game's clock started behind by every pause of the games before it, and below zero when that was longer than the new game had run.
29. `tjs2/tjs.h`, `tjs2/tjs.cpp`, `tjs2/tjsInterCodeGen.cpp`, `core/script/TVPScript.cpp`: a game whose `.exe` is Kirikiri 2 older than 2.29, read from its version resource, compiles a `var` declaration in a class or on global as an assignment that runs an inherited property's setter, as its engine did. Kirikiri 2.29 made such a declaration create a member that hides the property instead (krkr2 commit `b8e5b52`). Test Game 03, built on 2.18, declares `var face` in its MessageLayer and sets `Layer.face` through it, so on 2.29 semantics its message layer filled itself with opaque black over the title. `TVPInitScriptEngine` also resets the TJS compatibility options for each game.
30. `core/utils/TVPSettings.cpp`: a game's `<exe>.cf` is read as on Windows, one `NAME="VALUE"` line per option with the value a TJS string, and its options rank below the command line. A `.cf` cannot choose the renderer, the window, the draw threads, the game root, the AppData and Documents folders, or a program to run, and cannot turn on `-forcelog`, which opens its log file while options are still being read and aborts the engine. `-datapath` now moves `savedata/`. Its macro `$(exepath)` names the game folder, `$(appdatapath)` and `$(vistapath)` the folder `System.appDataPath` reports, and `$(personalpath)` and `$(savedgamespath)` the one `System.personalPath` reports. A relative path is in the game folder, and a path outside those three folders is ignored. A quoted option value is parsed as a TJS string. A project folder given without a trailing slash gets one, so `.../data` works like `.../data/`.
31. `core/main/TVPSystem.cpp`: the data folder is created once per path instead of once per process, so the next game in the same process gets its own. The unused `.cf` and embedded option stubs are removed.
32. `plugins/LayerExSave.cpp`: upstream's file was empty. It now registers `layerExSave.dll`, written from the plugin's manual and wamsoft's source, with the `Layer` methods games call: `saveLayerImagePng` and `saveLayerImageTlg5`, which save through `Layer.saveLayerImage` without the plugin's tags or PNG compression level, and `getCropRect`, `getCropRectZero`, `getDiffRect`, `getDiffPixel`, `oozeColor`, `copyBlueToAlpha`, `isBlank`, and `clearAlpha`. krkrsdl3 keeps pixels as R, G, B, A bytes where Windows Kirikiri keeps B, G, R, A, so these read blue from the third byte and store colors with red and blue exchanged. The asynchronous `Window.startSaveLayerImage` family, `saveLayerImagePngOctet`, `saveProvinceImage`, and the statistics methods (`getAverageColor`, `getFingerPrintValue`, `getShrinkVectorOctet`, `Math.octetVectorSum`) are not implemented, since no tested game calls them.
33. `plugins/TVPPlugin.cpp`: `addFont.dll` loads with the engine's internal plugins, since Kirikiri Z games call `System.addFont` without linking it.
34. `core/main/TVPWindow.cpp`: closing a window holds a reference to its script object while it is invalidated. Invalidating the window invalidates its layers, and when they held the last references to it, the object was deleted while its `tTJSNI_Window::Invalidate` was still walking the objects added to it, which crashed on quit.
35. `core/media/image/SaveTLG5.cpp`, `core/media/image/SaveTLG6.cpp`: the encoders write each pixel's blue, green, and red in that order, as the format and the loader expect. They wrote the image's bytes in memory order, R, G, B, so a saved TLG loaded with red and blue exchanged.
36. `core/utils/TVPSettings.cpp`: the game's `.exe` keeps its file name's case. The folder lister lowercases names for the auto path table, and the engine opens the `.exe` and its `.cf` by path, which is case sensitive on iOS. There `KHK_dx.exe` became `khk_dx.exe`, the version check could not read it, and Test Game 03 lost its Kirikiri 2.18 `var` semantics.
37. `core/media/movie/krmovie.cpp`, `core/media/movie/krnull.h`: every `VideoOverlay` mode plays through VNDegen's player in `vndegen/movie_player.cpp`. A movie it cannot open, such as one in a format the FFmpeg build leaves out, is logged and replaced by change 3's null player, so a game waiting on it continues.
38. `core/main/NativeEventQueue.cpp`, `core/main/NativeEventQueue.h`: each posted event carries its message number, so `Clear(msg)` removes only that kind. Upstream posted every event as message 0, so `VideoOverlay`'s clearing of stale `WM_GRAPHNOTIFY` events removed none of them. `Deallocate` clears the owner's queued events, which would otherwise reach a deleted `VideoOverlay`, and `Clear` does nothing once the application is gone at shutdown.
39. `core/render/TVPCompositor.cpp`, `environ/PlatformView.h`: a sprite can carry a placement, a rectangle in the window's content pixels, and is then drawn over that part of the content, scaled and letterboxed with it, instead of filling the window. Overlay-mode movies use it for `VideoOverlay`'s position and size.
40. `core/script/tjsNativeVideoOverlay.cpp`: reopening the movie that a closed `VideoOverlay` keeps cached reuses that player, which reads its own stream, and leaked the stream `Open` had just created. That stream is now deleted.
41. `environ/PlatformAudio.h`, `environ/sdl3/sdl3_audio.cpp`: a sound buffer reports `GetQueuedSamples`, the sample frames appended but not yet taken by the device, which the movie player's clock reads, and `Flush` marks the end of the appended audio. SDL holds back the last few samples of a stream it resamples, such as 44.1 kHz movie audio on a 48 kHz device, until the stream is flushed.
42. `core/main/TVPApplication.cpp`: `OnExit` deletes the movie players still alive once the script engine is gone, through `VNKKDestroyMoviePlayers`. Engine shutdown deletes leftover script objects without invalidating them, so a `VideoOverlay` a game never closed kept its player, whose decoder thread then read a sound buffer that `SDL_Quit` had destroyed and crashed the process.
43. `core/main/WindowManager.cpp`, `environ/sdl3/sdl3_app.cpp`: engine shutdown clears the table of keys and mouse buttons held down, and on iOS the fingers on the screen. A game that quit while Control was held left it down for the next game in the process, which then skipped through its text.
44. `core/main/TVPApplication.cpp`, `core/main/TVPApplication.h`, `core/main/NativeEventQueue.cpp`: `ProcessMessages` takes each message off the queue just before it runs it, and `NativeEventQueue::Clear` removes messages through `CancelUserMessages`, so clearing reaches messages of the batch already running. Upstream moved the whole batch out of the queue first, so when an earlier message deleted a `VideoOverlay`, its later messages in the batch still ran on the deleted queue. Messages posted while a batch runs still wait for the next call.
45. `core/utils/TVPSettings.cpp`: change 30's `-datapath` is resolved the way the engine reads it before it is checked: a component of n dots is n - 1 folders up, so `$(exepath)/.../x` named a folder two levels above the game, and symbolic links are followed to their real folder. A path whose real folder is outside the game folder and the AppData and Documents stand-ins is ignored, and the saves go to the real folder.
46. `core/archive/XP3Archive.cpp`: the extraction filter's `tTVPXP3ExtractionFilterInfo` keeps a reference to the file name, which was a temporary destroyed before the filter ran. A game's `xp3filter.tjs` read it on every filtered read.
47. `tjs2/tjs.cpp`: the script block, object, and register heaps that change 14's pools clear when a script engine is deleted hold the objects of every engine in the process, and a game's `xp3filter.tjs` runs in engines of its own, one per thread that reads archives. Only the last engine to be deleted now clears the heaps. Any other engine deletes only its own script blocks, which point back at it. Before, deleting the game's engine deleted the filter engines' objects too, among them the reserved word table they shared, and the next game's engine reused it after it was freed.
48. `plugins/xp3filter.cpp`, `plugins/xp3filter.h`, `core/main/TVPApplication.cpp`: engine shutdown stops the movie decoders, through `VNKKStopMovieWorkers` in `vndegen/movie_player.cpp`, before it deletes plugins and the script engine, since a decoder reads its movie on its own thread through the game's `xp3filter.tjs`. Just before the game's script engine goes, `TVPClearXP3Filter` deletes the filter engines and removes the game's filters. They used to stay for the next game in the process, which then read its archives through the previous game's filter.
49. `core/archive/TextStream.cpp`, `core/archive/TextStream.h`, `core/main/TVPApplication.cpp`: engine shutdown forgets the text encoding a game chose with `Storages.setTextEncoding` or `Scripts.setDefaultEncoding`. Test Game 75 chooses one, and the Shift_JIS games run after it in the same process failed to start with `Cannot convert given narrow string to wide string`.
50. `tjs2/tjsVariantString.cpp`, `tjs2/tjsConfig.cpp`, `core/archive/TVPStorage.cpp`: `TJSGetShorterStrLen`, `TJS_strcpy_maxlen`, and the UTF-16 length count in `TVPStringFromBMPUnicode` stop at their length limit before they read the next character. They read one character past the limit, so a string built from a single character, as `ttstr::IndexOf(tjs_char)` builds one, read past it. Every `.cf` `-datapath` did that, and AddressSanitizer stopped the engine on it.
51. `core/utils/TVPSettings.cpp`: change 45's `-datapath` gets a closing slash before it is resolved. Without one, the storage name normalizer leaves a last `.` or `..` unresolved, and `$(exepath)/save/..` kept `savedata/`. The walk up to the path's deepest existing part checks each part without its closing slash, and that part must be a folder. `lstat` follows a link named with a closing slash, so a link to nowhere or a link loop read as missing, and macOS's `realpath` takes a file named with a closing slash, so the engine accepted folders it could not write. VNDegen's save mapping in `EngineKiriKiri` resolves the path the same way, and both are tested against the cases in `Packages/VNDegenKit/Tests/EngineKiriKiriTests/Fixtures/datapath-cases.tsv`.
52. `core/main/TVPWindow.cpp`, `environ/PlatformView.h`: a modal window's loop, which holds the main thread until the window closes, calls a hook that `TVPSetModalLoopHook` installs on every pass, and closes the window as its close button would when the hook returns true. KAG's Yes/No dialogs are such windows. VNDegen's hook in `vndegen/vnkk.mm` runs the host app's events there, which its frames otherwise leave to the host, so the player's input can answer the dialog, and closes the dialog once the host ends the game.
53. `core/script/tjsNativeMenuItem.cpp`, `core/script/tjsNativeMenuItem.h`, `core/archive/TVPStorage.cpp`, `core/archive/TVPStorage.h`: a window's own `MenuItem`, its menu bar, which the engine never draws, asks a hook that `TVPSetMenuBarShownHook` installs whether to report `visible` as the game set it or as false. Without a hook it reports false. VNDegen's hook in `vndegen/game_menu.cpp` decides once per game, on the game's first read. The player can pick either answer on the game page. Automatic reports false when one of the game's scripts tests the menu bar for false, such as `kag.menu.visible == false` or `!kag.menu.visible`, since such a game puts its menu commands on screen then, as Test Game 71 does. Otherwise it reports what the game set, so a game such as Tawawa, which builds its menu only when the menu bar shows and has no on-screen fallback, builds it, and VNDegen lists it in its Game commands through `vnkk_menu`. The test is `vndegen/menubar_scan.cpp`, checked by `KiriKiriMenuBarScanTest`. It looks only at code: TJS outside comments and string literals, and in a KAG scenario the `exp` and `cond` attributes of its tags and the TJS between `[iscript]` and `[endscript]`. It reads each `.ks` and `.tjs` name in the game's auto search paths once, through the archives' ciphers, from wherever the engine's own lookup finds that name, so a script a patch archive replaces is read only in its patched form. `TVPListAutoPathStorages`, which this change adds, lists the names. The log names the file and line that decided, or says none did, with the time it took. The test reads a line at a time, so a condition split across lines isn't seen, and it reads only the names in the auto search paths, not scripts a game loads only from its current folder. No library game does either.
54. `environ/sdl3/sdl3_app.cpp`: the engine tick of the last frame `TVPDrawSceneOnce` drew, which paces a modal window's loop, starts at zero with each game, where change 28 resets the clock. It was a function-local static kept from the previous game, while each game's clock starts again at zero, so a later game's first modal window slept until its clock passed the previous game's last modal frame. KAG's Yes/No dialog then went undrawn and ignored input for up to minutes. The engine's other time stamps belong to objects each game creates, such as the system control and the TJS timer thread, or are reset as the game starts, as `StartApplication` resets the timer wheel's.
55. `environ/sdl3/sdl3_app.cpp`, `environ/PlatformView.h`: `SDL_AppEvent` first offers every event to a hook that `TVPSetHostEventHook` installs, and skips an event the hook handled. It runs in a frame and in a modal window's loop alike. VNDegen's hook in `vndegen/vnkk.mm` delivers the text that `vnkk_text` queues as an event of its own, so a character reaches the game after the key presses sent before it, including into a text field in a modal window.
56. `environ/unix/unix_file.cpp`, `environ/sdl3/sdl3_file.cpp`, `core/archive/TVPStorage.cpp`, `plugins/fstat.cpp`, `plugins/sqlite3/sqlite3.cpp`, `core/utils/TVPSettings.cpp`: a game finds its loose files and folders whatever case it names them in, as on Windows, on iOS and on case-sensitive Mac volumes. `tTVPFileMedia::GetLocallyAccessibleName`, which every read, write, existence check, and listing of a loose file goes through, resolves the path with `casepath_resolve` from `Engines/Shared/casepath.c`, which the RGSS engine shares. It lists only the folders below the deepest one that exists as written, prefers an exact name to one that differs in case, and caches each folder's listing until the folder changes. Upstream listed every folder from `/` down on each lookup, took the first name that matched ignoring case, and on iOS, whose sandbox refuses to list the folders above the app's own, resolved nothing. The first name that matches nothing, and the rest of the path, stay as written, so writing a file that exists in another case replaces it, and a new file goes into the existing folder of another case instead of a second folder such as `SaveData/` beside `savedata/`. A closing slash is kept. Upstream dropped it from paths it found, so `Storages.dirtree` joined a folder and the names in it without one. Creating, removing, renaming, and copying files and folders, and opening a database, drop the cached listing of the folder that changed, for file systems whose folder times are too coarse to show it. Folder listings, for `getDirList`, `fstat`'s `dirlist`, and the font scan, give names as on disk, as Windows does; the auto path table lowercases its own keys, which upstream's lister lowercased for it. Since both names of a move or copy that differs only in case now resolve to the same file, `fstat`'s `moveFile` then does nothing, and `TVPCopyFile` of a path onto itself does nothing. Copying would have truncated the file, and the move would then have deleted it. `CMakeLists.txt` builds `casepath.c` into the engine, and `scripts/kirikiri-engine.sh` counts `Engines/Shared` in its up-to-date check.
57. `core/media/font/TVPFont.cpp`, `TVPFont.h`, `FreeTypeFontRasterizer.cpp`, `plugins/LayerExDraw/LayerExDraw.cpp`: Windows fonts a game names and doesn't ship, such as ＭＳ ゴシック or Arial, draw in their substitutes from VNDegen's font table (`Engines/Shared/vnfont.h`, see `docs/fonts.md`), which `vnkk_set_fonts` hands the engine. `Font.getList` lists every substitute under its Windows name, and `TVPFindFont` and `TVPFontExists` also resolve names the table matches in another spelling, such as other case or full-width letters. A game that ships no `default.ttf` gets ＭＳ Ｐゴシック, the Windows engine's default, as its default font, and the bundled Droid Sans Fallback then draws only the characters the requested font lacks. Upstream used Droid Sans Fallback for every font the game didn't ship. A character the font lacks is measured from the fallback face as well as drawn from it, for `GetTextExtent` and `GetGlyphDrawRect`, where upstream measured it as a full square or an empty box. Each `vnkk_set_fonts` drops the substitutes registered for an earlier game and registers the current ones, so fonts the player removed between games are gone. A font file the game ships or adds under a substitute's name replaces the substitute's entry, and the flag that marks an entry as a substitute goes with it, so a refresh never removes the game's own font. `Font.getList` now lists the last font too; upstream's loop stopped before it. `LayerExDraw`'s `addPrivateFont` keeps Droid Sans Fallback for a substitute's name, since its renderer has no per-character fallback and the substitutes cover fewer scripts. The log names each substitute when it opens. `CMakeLists.txt` builds `vnfont.c` into the engine.
58. `core/script/tjsNativeSystem.cpp`: `System.checkAppId`, a property the engine build of some games adds, holding an id compiled into the `.exe`. Agent Shion and Kagachi-sama quit at startup unless it equals `global.APP_ID` from their own script, so it reads that.
59. `environ/sdl3/sdl3_audio.cpp`: with the environment variable `VNKK_AUDIO_LOG` set, each sound buffer logs its format, the frames appended, and their peak about every two seconds, so a test can confirm sound without hearing it.
60. `plugins/AlphaMovie.cpp`: a frame stores only the rectangle it covers, and the header fields upstream read as the alpha channel's size are its position. Each frame now goes at that position on a picture cleared first, clipped to the screen. Upstream drew it at the top left over the previous frame and uninitialized memory. The header field upstream skipped is the frame rate's scale, so a clip at 29.97 frames per second, stored as 2997 over 100, no longer plays as fast as frames come.
61. `core/render/TVPCompositor.cpp`, `environ/sdl3/sdl3_app.cpp`: the game's own Display menu options apply. `-fszoom` picks how the picture fits VNDegen's window: `inner` fits it inside, as before, `outer` fills the window and cuts off what doesn't fit, and `no` draws it unscaled in the center. Input follows through the sprite's scale and position. `-smoothzoom=no` scales the picture without smoothing. The `middle` zoom is left out, since games enable it only for their own stand-in for full screen on Windows.
62. `core/main/SystemControl.cpp`, `core/main/SystemControl.h`: `-contfreq`, the game's frame rate limit, holds back continuous events when it is below the 60 frames a second the host runs at.
63. `core/utils/TVPSettings.cpp`: `<exe>.cfu` in the data folder, where the game's Display menu saves its choices, is read as on Windows and ranks above the `.cf`. It follows the `.cf`'s rules, except that it can set `-smoothzoom` and a `-drawthread` that isn't negative, since the player chose them. Windows Kirikiri writes the file in UTF-16 and escapes everything but ASCII, so the reader drops the byte order mark and the zero bytes, and a save from a PC reads the same. `-fsres` is always `nochange`, since VNDegen never changes the screen's resolution and games test it to decide whether their zoom options apply.

Engine shutdown runs `tTVPApplication::OnExit`, which runs the at-exit handlers that `TVPAddAtExitHandler` registered, deletes the script engine and every script object it leaked, and clears the auto path table and the windows. `vnkk_stop` also resets `vnkk.mm`'s own per-game state. Together they let `vnkk_start` run another game in the same process. `KiriKiriRestart`, built by `scripts/kirikiri-engine.sh <dest> restart` or `restart-asan`, runs a list of games that way, checks that a modal window opened at each game's title draws and closes at once, and reports the memory and file handles each one leaves behind. A game can also quit midway through its first movie. `scripts/kirikiri-movie-quit-check.sh` does that with `vndegen/movie-quit/`, a script-only game whose movie is read through its own `xp3filter.tjs` and is never closed.

Text files without a byte order mark are left as upstream decodes them. krkrsdl3 tries strict UTF-8 first, then Shift_JIS, then GBK. Real Shift_JIS text is not valid UTF-8, so Japanese scripts decode as Shift_JIS, as on Windows. UTF-8 fan translations also keep working.
